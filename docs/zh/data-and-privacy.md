# 数据与隐私

> 你用的是自己的浏览器、自己的登录会话。这一页说明：数据从哪来、经过哪、存到哪、哪些不做。

---

## 1. 为什么必须用你的浏览器 + 扩展

服务端采集器会被平台识别和封禁。MonsterGet 的方式是：

```text
你的 AI 客户端 → 下发任务 → 你的浏览器打开目标页面
→ 扩展在真实登录会话里读取公开数据 → 回传 CSV
```

所以：

- 不需要 API key。
- 不需要把账号密码交给任何服务器。
- 平台看到的是你本人正常的浏览器会话。

代价是：**扩展、monsterget.com、目标平台登录必须在同一个浏览器**，采集时窗口要保持可见。

---

## 2. 采集的是什么数据

只采集**公开页面**上你本来就能看到的数据：

| 平台 | 典型字段 |
|---|---|
| TikTok | 视频描述、播放/点赞/评论/分享、作者、粉丝数、评论正文 |
| X | 推文正文、互动数、作者资料、评论 |
| LinkedIn | 公开档案、岗位、人员搜索结果的公开字段 |
| Upwork | 公开岗位、预算、技能、提案数 |
| App Store / Google Play | 评分、标题、正文、时间、版本、国家/语言、开发者回复 |

不采集：私信、私密账号、登录凭证、支付信息、未公开数据。

---

## 3. 数据经过哪里、存到哪里

| 环节 | 说明 |
|---|---|
| 采集 | 在你的浏览器里完成 |
| 临时中转 | 服务器只做任务结果的中转；结果被取走后删除，最长保留 24 小时 |
| 落盘 | CSV 保存到你本机的下载目录 / 运行目录 |
| 分析 | 在本机用 Python 标准库计算，不上传你的 CSV |
| 报告 | `report.html`、`metrics.json`、`tables/*.csv` 都在本机 |

> 如果公司有数据合规要求，建议把运行目录放在受控磁盘，并定期清理 `runs/`。

---

## 4. 个人信息怎么处理

- 报告默认不展示用户名、头像、邮箱、电话。
- 引用评论时会清洗：邮箱、URL、@handle、电话号码。
- LinkedIn 类分析只做公司/岗位维度聚合，不输出个人联系方式清单。
- 不推断年龄、性别、收入、健康等敏感属性。

如果你在 CSV 里看到个人信息，那是原始公开页面的一部分；**不要把它放进对外报告**。

---

## 5. 账号风险：必须说清楚

- 采集使用**你自己的账号**。
- 批量采集可能违反平台服务条款（ToS），导致限流、验证、甚至封号。
- 平台风控随时变化；今天能采不等于明天能采。
- 建议：控制频率、不要多账号轮换、不要采集私密内容、不要用于骚扰/诈骗/出售名单。

MonsterGet 提供的是工具，**账号和合规责任由使用者承担**。

---

## 6. 合规红线

| 可以做 | 不要做 |
|---|---|
| 公开评论/视频/岗位/档案的聚合分析 | 批量私信、批量加好友、骚扰式获客 |
| 报告里引用脱敏原话 | 展示可识别个人信息、头像、联系方式 |
| 公司/岗位维度的招聘情报 | 出售个人名单、教"绕过限制" |
| 竞品公开内容对比 | 搬运受版权保护的内容、冒充他人 |
| App 评论主题分析 | 把开发者回复里的邮箱/电话放出来 |

---

## 7. 我们不承诺什么

- 不承诺"无限采集""破解""绕过登录"。
- 不承诺覆盖平台的所有数据（例如没有广告库、没有视频字幕、没有受众人口属性）。
- 不承诺数据永久可复现（平台内容会变；请保留 CSV 和 `manifest.json`）。
- 不承诺分析结论一定正确（样本、词典、时间窗都有边界）。

---

## 8. 你应该保留什么

每次分析建议保留整个 run 目录：

```text
runs/<run_id>/
  brief.json        你当时的需求
  raw/              原始 CSV
  manifest.json     抓了什么、多少条、什么时候
  metrics.json      所有指标
  report.html       最终报告
  tables/           明细表
```

这样：

- 报告里的数字可以回溯。
- 下次追问不用重抓。
- 换机器/换人也能复现。
- 平台数据变了，你还能说明"当时是这样"。
